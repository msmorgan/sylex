# Semantics spec catalog

The behavioural spec distilled from `lean/Semantics/Proofs/` (`lean-proofs-spec-catalog`), for
`semantics-rust-rewrite` to port as native Rust tests before Lean is retired. Each entry states an
obligation, a minimal setup, the expected result, and the Lean theorem(s) it came from, which pass
as of this catalog. Positive fragments are carried only where they are the sole evidence for a
constructor; the canon `.syl` cards are the positive corpus.

Entries marked FLAG DEFECT may depend on the Lean multi-use parameter resolution defect which
`docs/tickets/planned/discourse-core.md` fixes; verify them against that fix rather than porting their
expected results blindly. Behaviour the sources record as wrong or unchecked is not carried as spec;
it is fixed across the `discourse-*` tickets of `semantics-rust-rewrite`.

# Part 1: Core reference resolution


Scope: `lean/Semantics/Proofs/` DrtResolution, DrtRecency, DrtWitnesses, ContrastAnchor, CallerScope,
ReferenceScopes, BindingIdentity, HistoricalMove, MovementScopes, LinkedReadback, RefusalReachability.

Entry shape: `**obligation** [CR] — setup — expect — from: File.theorem`. A theorem name in `from:` is
Lean's; the file prefix is the Lean module under `lean/Semantics/Proofs/`.

Reading aids (terms the setups use):
- *Referent* = a mention in the discourse context: id (introduction order, higher = more recent), clause
  number, grammatical role (`subj` < `obj` < `other` in rank), determiner, plurality, and a payload
  (Card Types, zone, provenance). *Pending role* = a Referent re-mentioned in a direct argument slot of
  the clause being read (a clause-mate). *Current clause* = the clause number being read.
- "Bare pronoun" = `it`/`them` (resolved by nearest clause, then best role). "Demonstrative" = `that
  creature`, `that player`, `that card` (resolved by most recently introduced compatible Referent).
- "refuses X" = the checker returns exactly that refusal kind and nothing else.
- Expected-result shorthand `[]` = no refusals.
- FLAG DEFECT = depends on, or is exposed to, the Lean multi-use parameter resolution defect which
  `docs/tickets/planned/discourse-core.md` fixes (a Definition parameter used twice resolves its caller
  argument at its first use only). Such entries are marked and their setups are accepted only
  because later uses are unchecked, or the check is order dependent.

### 3. Contrast Anchor ("another"/"other" with no "other than")

Priority ladder from the glossary: (1) Source coordinated with the phrase; (2) the current member of a
distributive group the clause's subject names; (3) nearest earlier compatible mention in Reference
Scope (kind, Card Type, zone, controller; never the described thing, the Source, "you" or a Condition's
hypothetical); (4) a compatible particular of the same clause read forward; (5) the Source (Object) or
"you" (Player) [CR#109.5]. "Source fallback" below reads no Card Type.

- **Nearest earlier mention is the anchor (step 3): second "any other target" anchors on the first (*Arc Trail*)** — setup: "deals 2 damage to any target and 1 damage to any other target" — expect: one anchor, the earlier mention (determiner `target`, no Card Type) — from: ContrastAnchor.arcTrailAnchorsOnItsFirstTarget
- **No earlier mention: the anchor is the Source (step 5), even for a damage-event Source** — setup: header "this creature is dealt damage" (framed as a creature), effect "it deals that much damage to any other target" — expect: anchor `source` — from: ContrastAnchor.screamingNemesisAnchorsOnTheSource
- **"Another target creature" with nothing earlier anchors on the Source (the CR example)** [CR#707.11] — setup: "this creature deals 1 damage to another target creature" on a creature face — expect: checks `[]`; anchor `source` — from: ContrastAnchor.oliviaAnchorsOnTheSource
- **Reconfigure: "attach this permanent to another target creature you control"** [CR#702.151a] — setup: attachTo thisPermanent (target creature you control, other) — expect: `[]`; anchor `source` — from: ContrastAnchor.reconfigureAnchorsOnTheSource
- **"A permanent or player" is no particular, so a replacement's "another source" anchors on the Source (*Embermaw Hellion*)** — setup: "If another red source you control would deal damage to a permanent or player, it deals that much damage plus 1 to that permanent or player instead" — expect: no refusals; anchor `source` — from: ContrastAnchor.embermawHellionAnchorsOnTheSource
- **The Source fallback reads no Card Type: a creature-headed "other" on a noncreature Source** — setup: Equipment "Whenever another creature dies, draw a card" — expect: card checks `[]`; the trigger event's anchor is `source` — from: ContrastAnchor.okCreatureHeadedOtherOnANoncreatureSource
- **Same for a Vehicle that is not a creature when printed (*Goliath Truck*)** [CR#508.1a,301.7] — setup: Vehicle trigger "Whenever this Vehicle attacks, put two +1/+1 counters on another target attacking creature" — expect: effect anchor `source` — from: ContrastAnchor.goliathTruckAnchorsOnTheSource
- **An earlier mention need not be a target: "Choose a player. Each other player draws a card"** — setup: [choose a player; each other player draws a card] — expect: one anchor, the indefinite "a player" mention (not "you") — from: ContrastAnchor.otherPlayerAnchorsOnTheChosenPlayer
- **With no player mentioned first, "each other player" is other than "you"** — setup: [draw 2; each other player draws 1] — expect: anchor `you` — from: ContrastAnchor.otherPlayerAnchorsOnYou
- **Earlier mention is an indefinite object, not a target (*Contractual Safeguard*)** — setup: "Choose a kind of counter on a creature you control. - **Anchor on a trigger's earlier action target (*Phantom Blade*)** — setup: "When this Equipment enters, attach it to up to one target creature you control. - **Anchor on a tapped / fought / first target in a spell (*Deadshot*, *Ulvenwald Tracker*, *Feral Contest*)** — setup: "Tap target creature. ## Fragment-only constructors (positive fragments the canon `.syl` corpus lacks)
